MAHALAXMI DUDH KENDRA V2 — READ THIS FIRST

UPGRADING FROM V1
1. Extract the V2 ZIP into a NEW folder. Keep the old copy until V2 works.
2. Copy your existing .env into the new project root. Do not overwrite it with the example. Do not share it.
3. Keep the same MongoDB connection string to retain your database.
4. If using Docker Compose, keep the existing database container running. Avoid starting a second MongoDB service on port 27017. When continuing with the original container, run database stop/start commands from its ORIGINAL project folder. Docker Compose names volumes based on the project folder; starting Compose in a differently named folder can create an empty database volume.
5. In the NEW folder run npm.cmd ci, npm.cmd run build and npm.cmd start after stopping the old Node server with Ctrl+C.
6. npm.cmd run seed is non-destructive, but is not needed if the database already contains your catalogue/admin.
7. For a fresh install, follow the complete guide below.

NEW ADMIN FEATURES
Sign in as admin and open Products & stock.
- New product: enter a unique lowercase SKU such as amul-taaza-1l, name, pack size, category, price and opening stock. Each pack size has its own SKU.
- Upload: choose one PNG, JPEG or WebP image up to 2 MB. Live uploads are stored in UPLOAD_DIR (defaults to uploads). Keep this folder when moving the project.
- Receive stock: enter the newly arrived quantity. If you have 20 and receive 50, enter 50; the result is 70.
- Edit: update name, pack description, price, image or TOTAL stock. Setting total stock is different from receiving additional units.
- Delete: confirm deletion. Products referenced in any order cannot be deleted; set their stock to zero instead.
- Changes persist in MongoDB in live mode. Hosted demo changes remain in that browser only.

NAVIGATION
React Router uses hash routes, for example /#/admin and /#/orders. This works when refreshing the hosted demo. Use the Web lab footer link for academic examples.

ADDITIONAL PRACTICAL COMMANDS (PowerShell, inside the project)

npm.cmd run lab:node
Demonstrates files, buffers, streams and the event loop.

npm.cmd run lab:http
Starts a separate basic HTTP server at http://localhost:3100. Press Ctrl+C to stop it.

npm.cmd run lab:repl
Opens the Node REPL. Try products.map(p => p.price), then type .exit.

npm.cmd run lab:mongo
With MongoDB running and .env configured, creates, reads, updates and deletes a temporary document in a separate lab collection. It does not delete shop products.

npm.cmd run test:ui
Runs nine DOM interaction checks. These are not browser screenshots or pixel-layout tests.

npm.cmd run test:integration
Downloads a temporary MongoDB binary, creates an isolated replica set and runs the Postman collection through Newman. Requires network access and permission to run MongoDB. This failed to start MongoDB in the creation environment because a filesystem operation was denied; it is NOT reported as a passing integration test.

POSTMAN
Import the two JSON files in postman/. Select the local environment, supply your TEST admin credentials, a fresh test customer email, and a unique test SKU. The fixtures assume test-store coordinates 19.0085,72.8467. Use a disposable database, not real shop data. Run the collection in order. Export results for your practical record only after it passes.

EXPERIMENT 10

Render plus an upload disk may incur charges; review the hosting plan before provisioning. Do not claim cloud end-to-end completion until you deploy and verify it.

MAHALAXMI DUDH KENDRA
COMPLETE BEGINNER SETUP AND RUNNING GUIDE
Windows + PowerShell + VS Code

Hack Cadet, follow these steps one at a time. This guide runs the complete MERN application on your Windows laptop.

React displays the website.
Express and Node.js handle accounts, orders and admin actions.
MongoDB stores customers, products and orders.
Docker Desktop runs MongoDB for you.

Use Windows PowerShell for all commands below. You do not need to open Ubuntu or switch between Windows and Linux terminals.

IMPORTANT: Run commands individually. Wait for each command to finish unless the guide specifically says to keep it running. Copy only the command itself, not surrounding explanations.

======================================================================
8. GENERATE A SESSION SECRET
======================================================================

Run:

node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"

The terminal prints a long random string. Copy the entire string.

You will paste it into JWT_SECRET in the next step. This secret allows the server to verify signed login sessions. Keep it private.

======================================================================
9. FILL IN .env
======================================================================

Use the following structure, replacing EVERY placeholder:

MONGODB_URI=mongodb://127.0.0.1:27017/mahalaxmi?replicaSet=rs0
JWT_SECRET=PASTE_YOUR_GENERATED_RANDOM_STRING_HERE
ADMIN_EMAIL=YOUR_ADMIN_EMAIL_HERE
ADMIN_PASSWORD="CHOOSE_YOUR_OWN_STRONG_PASSWORD"
STORE_LAT=YOUR_SHOP_LATITUDE
STORE_LNG=YOUR_SHOP_LONGITUDE
APP_ORIGIN=http://localhost:3000
PORT=3000
NODE_ENV=development
VITE_API_URL=/

WHAT EACH SETTING MEANS

MONGODB_URI:
Keep the supplied value for this local Docker setup.

JWT_SECRET:
Paste the random string generated in Step 8.

ADMIN_EMAIL:
Enter the email address you want to use for admin login. This is a login identifier; this version does not send email verification messages.

ADMIN_PASSWORD:
Choose your own password of at least 12 characters. Keep the double quotes around the value. For straightforward setup, avoid using a double-quote character inside the password.

STORE_LAT and STORE_LNG:
Enter the actual shop's latitude and longitude.

To find them, locate the exact shop position in your map application and copy its coordinates. Latitude is the first number and longitude is the second.

For understanding the format only:
19.xxxxxx, 72.xxxxxx

Enter only a numeric value on each line. Do not include degree symbols, commas, or directional letters in the individual values.

These coordinates define the center of the 5 km delivery area. Use the actual shop location before accepting real customers.

APP_ORIGIN:
Keep http://localhost:3000 for this guide.

PORT:
Keep 3000.

NODE_ENV:
Keep development while running locally.

VITE_API_URL:
Keep /. This enables the real backend when the frontend is built.

Press Ctrl + S to save .env.

Do not publish or share this file. It contains private credentials.

MAHALAXMI V2 — WEB LAB EXPERIMENT MAP

1. Bootstrap registration + JavaScript validation
   src/components/AuthForm.jsx uses Bootstrap row/col-12, form-control, is-invalid and invalid-feedback. Explicit JavaScript validates name, email, password length and matching confirmation. Live registration is at /#/login. It requires VITE_API_URL=/ at build time and the running backend.

   src/components/ExperimentLab.jsx demonstrates arrow functions, anonymous functions, array.map, events, alert, confirm and prompt. Open /#/lab or Web lab in the footer. Production inventory also uses confirm before delete and prompt for stock receipt.

3. Functional React, JSX, props and state
   ProductCard receives product, image, quantity and onAdjust through props. AuthForm, InventoryManager and ExperimentLab are functional components. useState controls cart, forms, filters and edits.

   HashRouter with useNavigate/useLocation provides refresh-safe routes /#/, /#/orders, /#/admin, /#/cart, /#/login, /#/subscriptions, /#/retailers, /#/delivery and /#/lab.    compose.yaml configures a replica set. server/models.js defines products, users, orders and requests.    npm run lab:http starts a built-in Node HTTP server on localhost:3100. Open it in the browser; Ctrl+C stops it.
   npm run lab:node executes Buffer encode/decode, file write/read, stream pipeline and synchronous/microtask/timer logging. Output files are placed in labs/output.

   Import postman/Mahalaxmi.postman_collection.json and Local.postman_environment.json into Postman. Set admin credentials, a fresh customer email and a fresh SKU.    npm run test:integration starts a temporary MongoDB replica set and runs that same collection through Newman (Postman's CLI runner). Aggregate results, without credentials/cookies, are in docs/INTEGRATION_RESULTS.json.

   src/main.jsx calls the Express API using fetch with credentials. The integration suite validates persisted products, users, orders and requests. Set VITE_API_URL=/ for real local operation; unset only for the isolated hosted demo.

EXPERIMENT 10: FULL MERN CLOUD DEPLOYMENT

Status: deployment configuration is included. Full MERN cloud deployment has NOT been performed. The ChatGPT-hosted review URL remains a browser-local demo.

Required accounts: a Git repository host, Render, and MongoDB Atlas (or an existing MongoDB replica set). Credentials must be entered privately in the hosting dashboard, never in source files or chat.

1. Upload the project source to your own private Git repository. Exclude .env, node_modules and uploads. Keep package-lock.json.
2. Create a MongoDB Atlas database deployment and database user. Under Connect, select the driver/application connection option and copy the URI. Set the actual password and database name. Allow only the required application outbound IP ranges in Atlas Network Access.
3. In Render, create a Node web service from that repository. The included render.yaml is an optional Blueprint. It requests a Starter service plus persistent disk; review the displayed costs before provisioning.
4. Set build command: npm ci --include=dev && npm run build
5. Set start command: npm run seed && npm start
6. Configure VITE_API_URL=/ at BUILD time and NODE_ENV=production. Set MONGODB_URI, JWT_SECRET (32+ random characters), ADMIN_EMAIL, ADMIN_PASSWORD (12+ characters), STORE_LAT, STORE_LNG and APP_ORIGIN. APP_ORIGIN must exactly equal the HTTPS service origin, without a trailing slash. You can set it after Render assigns the URL and redeploy.
7. Set health path /api/health. Render provides PORT automatically.
8. Mount a persistent disk at /var/data/mahalaxmi and set UPLOAD_DIR to that path. Without persistent storage, uploaded product images may disappear after restarts/deployments. The included Blueprint configures this disk; it is not a free deployment configuration.
9. Set TRUST_PROXY_HOPS only if you have confirmed the number of trusted reverse-proxy hops in your actual hosting topology. Do not enable arbitrary proxy trust.
10. Deploy. Inspect logs for successful seed and server startup. Open /api/health and /api/products on the actual HTTPS domain.
11. Register a customer, create a temporary test SKU as admin, receive stock, upload an image, place an eligible test order, move it through every stage, and check customer order history. Use a test database before accepting real business orders.
12. Capture screenshots and API results from the deployed service for Experiment 10. Only mark it completed after this end-to-end exercise succeeds.

The Dockerfile is an alternative for a Node/container host. Mount /app/uploads persistently (or set UPLOAD_DIR), supply the same environment settings and run npm run seed once in the container before normal use. No cloud service has been provisioned by this package.
